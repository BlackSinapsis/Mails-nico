## Criterios de aceptación

- No hay DSO, CEI, forecast de caja ni cohortes.
- No hay un kanban de toda la gestión.
- No hay pixel de apertura ni de clic.
- No hay portal de pago, tarjeta ni débito.
- No hay informes escritos por un modelo, ni un modelo que clasifique la respuesta.
- Notas y tareas no son un módulo. El motivo de la pausa es el texto que hace falta.
- No se copia código AGPL ni comercial de Twenty, ni se importa `twenty-ui`. No hay `empresa_id`. La segunda empresa, cuando exista, es otra instancia.
- No hay Framer Motion, ni ticker de números, ni stagger de filas.
- No se separan el abono y los trabajos extra. No hay tabla de partidas. No se suman filas de una misma clave. No se implementa `POST /ciclos/desde-api`.
- No se mandan 600 mails. El tope de un envío es 150.
- No hay workflows, SMS, WhatsApp, conciliación bancaria ni editor de celdas.
- No se inscribe la base en AAIP en este piloto corto.
- No se cambia la clave del seed en este recorrido.
- No se abre el PR de documentación.
- No se pushea código a `OrderByte01/aldia` ni se toca `Juanrocod/Mails-nico` desde un ticket. No se renombra el código de la app para que diga Aldia: el nombre visible lo cambia Etiquetas, foco y estado visible cuando se tome.
